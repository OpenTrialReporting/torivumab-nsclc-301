## Tooling

| Script | What it does |
|---|---|
| `programs/qc/build_trackers.R` | Regenerates the 3 Excel trackers (see warning below) |
| `programs/qc/run_reproducibility_check.R` | Re-runs the full pipeline into a temp dir and diffs every output. Reports pass/fail per file. Optional `RERUN_RAW=1` and `TFL_REPRO_KEEP_STAGE=1`. |
| `programs/qc/compare_sdtm.R` | Compares two SDTM directories via `diffdf` + fallback `identical()`. Usage: `Rscript ... <primary_dir> <qc_dir>` |
| `programs/qc/compare_adam.R` | Same as SDTM plus Cox-HR + KM-median tolerance check on ADTTE. |
| `programs/qc/extract_tfl_values.R` | Parses `tfl/tables/*.docx` and dumps every cell to CSV. Allows `diff <(sort primary.csv) <(sort qc.csv)` style comparison. |
| `programs/qc/_compare_helpers.R` | Shared dataset comparison logic (key-resolution + fallback). |

All scripts run from the project root.

## Programming-tracker overview

Three Excel workbooks track double-programming QC across the project's
deliverables. Generated by `programs/qc/build_trackers.R` from the actual
file inventory + spec metadata.

| File | Rows | Covers |
|---|---:|---|
| `SDTM-PROGRAMMING-TRACKER.xlsx` | 21 | All SDTM domains in `datasets/sdtm/` |
| `ADAM-PROGRAMMING-TRACKER.xlsx` |  6 | All ADaM datasets in `datasets/adam/` |
| `TFL-PROGRAMMING-TRACKER.xlsx`  | 38 | All shells in `sap/shells/shells.yaml` |

## Sheets in each workbook

| Sheet | Purpose |
|---|---|
| `<X> tracker` | Main grid — one row per output. Programmer / QC programmer / dates / status / findings / lock. |
| `Status legend` | Definitions of the 7 status values, colour-keyed. |
| `Sign-off` | Final lock signature block (Lead programmer, QC programmer, Biostatistician, DM, PM, QA, Sponsor). |

## Status workflow

```
Not started
    ↓  (primary programmer writes code, generates output)
Programmed — pending QC
    ↓  (QC programmer assigned)
QC in progress
    ↓
QC passed — issues none            QC failed — under rework
   OR                                       ↓  (back to primary)
QC passed — minor issues resolved   Programmed — pending QC
    ↓
Locked
```

Status cells have a dropdown validation (in Excel/LibreOffice) constrained
to these 7 values, with conditional fills colour-coded per the legend.

## Pre-populated state

When the trackers are generated (or re-generated), every output that has
a corresponding committed artifact is initialised at:

- `Primary programmer`: blank — to be assigned by lead programmer
- `Programmed date`: today's date
- `Status`: `Programmed — pending QC`
- `QC programmer`, `QC dates`, `Findings`, `Resolution`, `Lock date`: blank

Outputs without an artifact (none currently — Phase 6 is complete) would
initialise at `Not started`.

## Regenerating

```bash
Rscript programs/qc/build_trackers.R
```

⚠️ This **overwrites** the Excel files. If trackers already contain
QC-progress data entered by reviewers, regenerate to a staging area
and merge by output ID before overwriting — do not regenerate blindly
once QC work begins.

## Double-programming reference specs

| Layer | Spec for re-derivation |
|---|---|
| Raw → SDTM | `programs/sdtm/SDTM-MAPPING-SPEC.md` |
| SDTM → ADaM | `programs/adam/ADAM-MAPPING-SPEC.md` |
| ADaM → TFL  | `sap/SAP.md` §13 (estimands), `sap/shells/shells.yaml`, `sap/shells/TFL-SHELLS-DOC.docx` |

Each QC programmer should reproduce the output using only these specs
(no reference to `programs/sdtm/*.R`, `programs/adam/*.R`, or
`programs/tfl/*.R`), then compare numerically with the production
output per the QC checklist at the bottom of each spec.
